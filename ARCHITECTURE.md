# Architecture — Food Safety Horizon Scanning

This document describes the actual current pipeline. It was written on
2026-07-30 after a code-level audit (see `EVALUATION_AMELIORATIONS.txt`),
not from a design spec — every claim below was verified against the code
and workflows in this repo. `README.md` (rewritten 2026-07-31) now covers
the project overview and acknowledgment; this file goes deeper on the
technical pipeline mechanics for anyone modifying it.

## Data flow

```
scrapers/<region>/*.py  (discover_scrapers() in pipeline/run_all.py)
        |
        v
  raw recall rows (per-scraper try/except; one failing scraper
  never blocks the others — see run_one_scraper())
        |
        v
  Gemini enrichment (pathogen/country/class/tier normalization)
  — skippable via SKIP_AI
        |
        v
  Pending sheet (docs/data/recalls.xlsx, deduped vs Pending+Recalls)
        |
        v
  URL validation (HEAD/GET) + Claude/Gemini review
  — skippable via SKIP_REVIEW
        |
        v
  Promotion: approved rows move Pending -> Recalls;
  rejected rows stay in Pending with a reason
        |
        v
  docs/data/recalls.xlsx (source of truth) + docs/data/recalls.json (public mirror)
        |
        v
  reports/*.py generators -> docs/*.html (dashboard, weekly/monthly/daily reports)
  published on GitHub Pages
```

Orchestrated end-to-end by `pipeline/run_all.py`, triggered by GitHub
Actions cron (see `.github/workflows/daily-scrape.yml`,
`morning-critical-scrape.yml`, `merge-master.yml`, and ~75 other workflow
files for the full schedule of scrape / gate / review / report jobs).

## Scraper layer (`scrapers/`)

Two scraper styles coexist:

- **Dedicated parsers** — custom logic per source, e.g.
  `scrapers/eu_wide/rasff.py` (EU RASFF JSON API) and
  `scrapers/north_america/usda_fsis.py` (USDA FSIS JSON API). No AI call
  needed; most mature and most heavily tested (see `tests/`).
- **`GenericGeminiScraper`** subclasses (`scrapers/_base.py`) — delegate
  HTML extraction to a Gemini prompt with an OpenAI (gpt-4o-mini) fallback
  on quota/rate errors. Used for ~64 lower-volume sources where writing a
  dedicated parser isn't worth it. Requires `GEMINI_API_KEY_1..5` (free
  tier) to function at all; raises a clear `RuntimeError` if no key is
  configured (does not silently fall back to fake data).
- **`BaseRegulatorRSS`** subclasses (`scrapers/rss_regulators/*.py`) — pure
  RSS/XML parsing, no AI needed. 8 sources (USDA FSIS, BVL/DE, EFSA/EU,
  Fødevarestyrelsen/DK, FSAI/IE, FSANZ/AU, FSS/Scotland,
  Livsmedelsverket/SE). Moved into this dedicated subpackage and wired
  into `discover_scrapers()` on 2026-07-30 — previously sat unused at the
  root of `scrapers/` (see `scrapers/rss_regulators/__init__.py` for the
  history).

`discover_scrapers()` (`pipeline/run_all.py`) walks a hardcoded list of
subpackages: `north_america, europe_eu, europe_non_eu, eu_wide, asia,
oceania, africa, latam, middle_east, rss_regulators`. As of 2026-07-30
this discovers 81 scraper instances. Any file left directly at the root
of `scrapers/` (outside a subpackage in that list) is NOT auto-discovered.

## API keys — where they actually live

Keys (`GEMINI_API_KEY_1..5`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`) are
read from environment variables. In production they come from **GitHub
Actions repository secrets** (`Settings > Secrets`), not from a local
`.env` file — see `.env.example` for the full list and
`scrapers/_base.py::_gemini_api_keys()` / `_call_llm()` for the
round-robin + Gemini-to-OpenAI fallback logic. Running the pipeline
locally without keys is safe: AI-dependent code paths raise an explicit
`RuntimeError` naming the missing variable rather than degrading silently.
`SKIP_AI=true` / `SKIP_REVIEW=true` disable the *post-scrape* enrichment
and review passes (not the in-scraper Gemini extraction used by
`GenericGeminiScraper`).

## Data reliability

- `docs/data/recalls.xlsx` is the source of truth (referenced across 46
  files under `pipeline/`); `docs/data/recalls.json` is a generated public
  mirror with internal columns stripped.
- Every row carries a `URL` (source link) and a `Notes` audit trail
  (`gemini-enrich`, `gemini-check`, `url-gate`, `manual-adjudication`
  stamps), letting any record be traced back to its origin and to the
  pipeline stage that touched it.
- `pipeline/claude_check.py::_pathogen_reason_class_mismatch` /
  `_classify_hazard` guard against the enrichment step inventing a
  Pathogen value that contradicts the Reason text — see
  `tests/test_hazard_class_guard.py` for the production incident that
  motivated it and the regression coverage now in place.

## Report / dashboard layer (`reports/`, `docs/`)

Static HTML/CSS/vanilla-JS, generated by Python scripts (`reports/*.py`,
`docs/build_*_report_afts.py`) and published on GitHub Pages
(`docs/index.html` and friends). No frontend framework or bundler.
`reports/_theme.py` holds shared color/badge constants
(`SRC_CSS`, `PBADGE`, `TIER`); `reports/dashboard.py` imports `SRC_CSS`
from it. There is currently no i18n layer — every generated page declares
`lang="en"`; French only ever appears as data content (e.g. source labels
like "RappelConso (France)"), never as an interface language.

`fsis_global.db` (SQLite, repo root) and `reports/dashboard.py`'s
`_get_all()`/`generate()` path are **not** part of this pipeline — see the
STATUS note at the top of `reports/dashboard.py`.

## Tests (`tests/`)

Offline, no network/API keys required — every scraper test mocks
`scrapers.<module>.fetch` directly (`unittest.mock.patch`) rather than
hitting the network. Run with `pytest -v` (also wired into
`.github/workflows/tests.yml` on push/PR to `main`). 364 tests pass as of
2026-07-30. Coverage is per-scraper-module for `usda_fsis`, `rasff`,
`rappelconso`, `cfia`, and `fsa_uk` — together these five account for the
large majority of production row volume; the remaining scraper modules
rely on the live weekly `audit-scrapers.yml` health workflow
(`pipeline/scraper_health_audit.py`) rather than unit tests.
